## 目标与范围

首个正式交付目标是约翰·法雷尔从新游戏到结局的全中文可通关路线，沿用现有 React + Canvas + TypeScript 架构与地图。首版完成后按独立路线继续完成其他五主角，最后叠加既有扩展设定。单一主角首版不是整个项目已经完成。

验收以真实玩家流程为准：理解目标、贸易与补给、探索与上报、人物事件、战斗胜败、成长、结局、保存后继续。工程测试是保障，不代替实际游玩。

## M0 实现边界

- 使用 Node.js 22，保留锁文件与现有依赖版本。
- 默认简体中文（zh-CN），可切换英文（en），语言偏好存储于独立的 `uw2.locale`，不改变 savedState 或存档版本。
- 不修改港口/物品/船只/角色 ID、菜单 action value 或剧情事件 ID；仅本地化显示文本。
- 现有英文剧情与等价测试保留，中文采用独立词典；动态文本使用明确参数插值，禁止通过模糊正则猜测整段渲染结果。
- 中文姓名与港口/商品/船名术语集中维护，未知专名记录为待核对，不把内部 ID 显示给玩家。
- 所有玩家可见入口纳入：HUD、菜单、建筑对白、物品/船舶/伙伴信息、发现、系统、开场剧情、加载与操作说明、图片中的确认字样。
- 语言切换不丢进度、不重新开始剧情、不改变金钱/船员/事件结果；中文对话可阅读，不溢出固定窗口。
- 海上首次启动及读档重建世界时，必须先初始化风与洋流，不依赖时间恰好为 240 分钟的倍数。
- 通过具有真实状态恢复路径的回归测试、全部既有单元测试、类型检查、代码规范、生产构建和浏览器验证。

## 内容与剧情的扩充约束

用户于2026-09-06追加要求：本轮实现要考虑未来扩充游戏内容和剧情。这是持续实施约束。

- 沿用显式注册的 StoryArc / StoryEvent，按章节维护角色、对白、条件和奖励；复刻主线、支线及扩展设定通过章节依赖接入。既有ID保持稳定，新内容不能靠改写旧章节或到处新增特殊分支推进。
- 显示层按用途与章节组织：通用界面、专名、各章节对白分开，`localization/dialogue.ts`只作为对白模块的汇总入口。新增章节带上中英文内容覆盖及参数校验。
- 内容继续使用声明式条件和效果，禁止把任意回调放进剧情数据。新条件/效果同步扩充类型、校验器、执行器和对应行为测试。
- M1实现通用事件完成记录和发现上报的存档迁移，解除当前仅有里斯本旧任务完成键可保存的限制；旧存档的奖励不得重新发放。当前M0只做准备，不冒称通用新章节保存已完成。
- 每个章节验收进入条件、出口、拒绝/失败路径、奖励只发一次、保存后继续，以及已有章节回归。以后增加人物、船只、物品或发现物时检查引用和界面容量。
- 保留既有“复刻基线之上叠加扩展”的方向。扩大内容量与增加新系统分开验收，避免一次改动同时改变所有路线的规则。
