### D10 — 市场采用单一参考价 + 固定价差 + 相场指数
- 日期：2026-08-13 · 来源：`docs/superpowers/specs/2026-08-13-market-price-dynamics-design.md`
- 起因：原 Market MVP 的买价 / 卖价是两个**互相独立**的函数，凡在 `demands` 而不在 `supplies`
  的商品即 `卖价 > 买价`，**同港套利**，全 13 市场共 55 对（里斯本 Pepper 150 进 270 出）。
- 决策：买卖价统一由**单一参考价**（基准价 × 区域倍率 × 相场/100）加 **±10% 价差**导出，
  使 `买价 > 卖价` 成为**结构性不变量**而非数值巧合；回归测试扫满 13×24×161 全组合。
- 相场指数每（市场×商品）一个，`[40,200]`，买推高卖压低；交易**按块结算**，
  故倾销边际收益递减。回归到 100 用**惰性计算**（存 `updatedDay`，读时推导），
  刻意不挂日 tick——纯函数、无世界循环耦合、跨存档与长时间间隔均正确。
- 存档升到 v3（沿用 D6 的迁移链），仅新增 `marketPrices`；`quests` / `fame` 不动，
  故 D8 的 Save v2 剧情兼容边界不受影响。

### D11 — 断粮惩罚：逐日结算 + 减员，全灭拖回最近港口
- 日期：2026-08-13 · 来源：`docs/superpowers/specs/2026-08-13-starvation-penalty-design.md`
- 起因：`getProvisionSummary` 早就会算出 `'exhausted'` 并标红，但**没有任何后果**，
  于是「买多少补给」不是决策、航行零风险，补给 UI / 补给港 / 占用的货舱全成摆设。
- 结构性前提：原 `planProvisionConsumption` 把整段天数**一次算完**，说不出「哪几天断粮」，
  而减员会降低次日消耗——天与天不独立。因此整段计算**必须**换成逐日推演，这是本切片的技术核心。
- 惩罚：缺水或缺粮当日按 `ceil(船员 × 10%)` 减员，两者皆缺翻倍；从当前人数最多的船逐人扣，
  结果确定可测。因消耗随人数下降，死亡螺旋自限。
- 全灭处理：`shipSpeed` 的 `navigationCrewFactor = min(1, crew/minimumCrew)` 在 crew=0 时速度归零，
  放着不管是**永久卡死**而非惩罚。故船员归零即结束航行、按直线距离拖到最近港口正常靠岸；
  货物 / 金钱 / 物品 / 剧情进度均不动。惩罚是整船船员与时间（重新雇人本就花钱），**不另造惩罚机制**。
- 不动存档：船员在 `ship.crew`、位置在 `fleets['1'].position`，已在序列化范围内，无需迁移。

### D12 — 探索发现用自建史实地标集，坐标由真实经纬度经投影推导
- 日期：2026-08-14 · 来源：`docs/superpowers/specs/2026-08-14-discovery-mvp-design.md`
- 数据源选择：**不接 50 条 lore**（`relicData` / `legendData` / `tradeGoodData`）。
  它们还背着 D7 否决后的「去机器」改写债、且 `triggers`/`rewards` 全空。
  改为自建 14 条纯史实地理地标（直布罗陀 → 麦哲伦海峡），无改写债、可独立完成。
  lore 作为内容层日后随时可叠加。
- 奖励：看见即得**冒险名声 + 金币**，一次性永久。这激活了 `state.fame`——它此前
  已序列化、已是合法剧情触发条件（`fameAtLeast`），却没有任何东西授予或显示它。
- **金币是临时安排**：原作是「发现 → 回港上报 → 领赏」，上报那步才是回港动力。
  上报系统落地后，金币移到上报，看见只给名声。已写入 spec，不留成暗债。
- 坐标方法（重要）：地标声明**真实经纬度**，地图坐标由有文档的投影推导，禁止手写 x/y。
  经度刻度**不拟合**——地图宽 `WORLD_MAP_COLUMNS` 且横跨 360°，故恰为 6.0 单位/度；
  环绕直接复用同一常量，不再本地复制，避免与 `getXWrapAround` 漂移。
  纬度需拟合（地图是裁剪的，约 87.6°N–60°S）。
- 半径由**每 tick 最大位移**反推（实测 1.0 单位，取 5）：半径小于单 tick 行程时，
  船会直接穿过地标而静默不触发——玩家体验为「我明明开过去了却没反应」。
- 评审教训：本切片第一版**全部测试通过而 14 个地标错了 10 个**。原因是 spec 给的判据
  （「离参照港 120 单位内」）与数据同源，二者相符不构成证据。故新增
  `discoveryData.geography.test.ts`，判据取自 `portData` 而非 spec：
  检查每个地标最近的**游戏港口**是否为现实中确实相邻的港口。

### D13 — 船队位置由世界循环每 tick 发布回 state；发现与名声上界面
- 日期：2026-08-14 · 来源：`docs/superpowers/specs/2026-08-14-discovery-ui-design.md`
- **发现的既有 bug**：`createWorldPlayer` 捕获起始位置后，每 tick 是**重新赋值**自己的
  闭包变量，`state.fleets` 从来看不到船在动——整段航程停在上次靠岸/读档的位置。
  后果有二：`updateWorldStatus` 由该位置取海域，**离港后风向洋流再也不变**；
  D12 的地标发现读同一位置，**只可能在起航点触发**。
  决策：世界循环每 tick 发布已提交的格子位置回 `state`；`dock()` 仍负责写入靠岸终位置。
- 这个 bug 是**被一个测试逼出来的**：C2 要求「真的开船撞进地标」的浏览器测试，它跑不过。
  C1 自己的测试没发现，因为它们**直接设置位置**而不是驱动真实移动。教训：
  凡是「读取运行时状态」的功能，测试必须驱动产生该状态的真实路径，否则等于没测。
- 界面：横幅**不用计时器**（持续到被替换或靠岸清除），因为 `tests/e2e` 全仓库没有一个
  固定等待，不该由本切片开先例。名声与发现走**独立 updateInterface 通道**，
  不扩宽 `general` 载荷（调用点遍布全项目且被测试断言形状）。
- 名声读数比旁边的 Ingots/Coins **更紧凑**：三条按那个样式要占 180px，而 HUD 列只有
  800px 画框，会把面板顶出游戏区、压到下方页面文字上。画框改为顶部对齐，
  这样面板溢出时相机不会被切——海上视图在本切片之前就已经溢出（912px）。
  （溢出本身在 D14 才真正修掉；顶部对齐只是止血。）

### D14 — HUD 列高度固定为画框的 800px，超出的部分滚动而不是把列撑高
- 日期：2026-08-14
- **问题**：左列在海上实测 1080px、在港 836px，画框只有 800px，两种状态都溢出，
  海上尤其明显——底部的 Discoveries / System 菜单直接压在游戏下方的页面文字上。
  最大的一块是 `Provisions` 的四行补给：图标按 2x 画成 64px 高，四行 320px，
  占掉整列的三分之一。这段早于发现/名声切片，不是它引入的。
- 决策三条：
  1. `hudClass` 写死 `h-[800px]`，与中间的游戏视图同高。列**不能**再随内容长高；
     读数区 `overflow-y-auto`，菜单区 `shrink-0`，所以挤不下时滚的是读数、
     菜单永远贴在底部可点。顺带修好右列——它原本被左列 stretch 到 1100px，
     风向/洋流指示器是在这个高度里居中的，等于被推出画框。
  2. 补给图标改回**源图原尺寸** 16x32（原本 2x）。1.5x 会把 16px 宽的精灵
     一部分列翻倍一部分不翻，像素画会花；只有整数倍能选，而 2x 装不下。
  3. Ingots/Coins 从「标签一行、数值一行」改成与名声读数**同一个** `HudReadout`
     行内样式（省 56px）。D13 那条「名声比 Ingots/Coins 紧凑」的不一致就此消失：
     左列现在只有一种读数样式。
- 结果：海上 768/800、在港 732/800。`tests/e2e/hudLayout.cy.ts` 守住这个预算——
  只测列高会永远通过（列已经写死 800），所以真正咬人的断言是
  **读数区 `scrollHeight <= clientHeight`**，即正常状态下不该滚。
- 唯一会滚的是断粮：两条警告同时出现、在 180px 宽里各折两三行。
  这时滚掉的是下面的木材/弹药行，警告本身留在视野里。

**工程债（2026-08-14 记录，均在切片 B/A/C 期间发现，不影响已推送代码的运行）**
- [E1] **prettier 长期无人把关**：`npx prettier --check src/ tests/ scripts/` 报 16 个文件不合规，
  含 `System.tsx`、`legacyLisbonSnapshot.ts`、`validator.contract.test.ts` 等从未被本轮触碰的文件。
  根因：`verify` 只跑 eslint 不跑 prettier，而 `eslint-config-prettier` 把 eslint 的格式规则全关了；

  **补这个缺口会让 CI 立刻变红直到 16 个文件全修完**，所以要么一次性全修+入 `verify`，要么继续不管，
  不建议半修。
- [E2] **husky 钩子按检出位置而定，且在 worktree 里是坏的**：`extensions.worktreeConfig = true`，
  主检出 `core.hooksPath` 未设置（→ `.git/hooks`，无 `pre-commit`，钩子不执行）；
  但每个 agent worktree 的 `config.worktree` 设了 `core.hooksPath = <repo>/.husky`，
